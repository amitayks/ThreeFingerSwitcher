## Why

Today an AI command **auto-fires** the moment it is lifted: acquire input → resolve the preset template → stream → resolve with the canonical two-finger compass (down=apply, horizontal=discard). The canvas is a one-shot preview of a single preset's output. That is the v1 grammar, and it is the front end the whole V2 on-device **agent** vision sits behind.

V2 turns that one-shot surface into a **conversational canvas**: a typed, multi-turn thread that opens **showing the copied seed and waiting** (a placeholder, not an auto-fired preset), floats the placeholder up off the seed the instant the user types, streams an assistant reply, accepts the next typed turn, and resolves the latest answer with the **same** canonical compass. A preset (Fix Grammar, Translate, "Ask…") becomes nothing more than a **pre-filled turn 1** of that exact same thread — one canvas, one state machine, every entry point.

The conversation types (`AgentConversation`/`AgentMessage`/`AgentSessionID`), the per-turn session machine (`.conversing`/`.awaitingTurn`), the route→execute→continue loop + its DOWN=approve/RIGHT=skip approval contract, and the `ParkedSession`/overscroll-park scheduler are **owned by earlier waves** (`ai-conversation-runtime`, `ai-tool-routing`, `ai-parked-sessions`). This slice is the **front end**: it consumes those contracts and builds the seed → float-up → multi-turn → gesture-compass UX over the existing `AICommandCanvasView` + `BubbleMorph`, adds only the canvas-level `State` cases it owns, and wires the overscroll-park trigger the parked-sessions slice consumes. It is MLX-free Core + a SwiftUI overlay view, verified end-to-end under `swift test` with `StubLLMRuntime`.

## What Changes

- **Seed model — open showing the seed, WAIT (no auto-fire).** Triggering AI with copied content (`selection`/`clipboard`/`clipboardImage`/`screenRegion`) opens the canvas **displaying the seed as turn 1's user message and idling in `.awaitingTurn`** — it no longer auto-streams a preset. A new executor entry (`startConversation(seed:)`) replaces the auto-`fire` for the conversational (empty-question) path; the preset path (Fix Grammar etc.) is the *same* entry with turn 1 pre-filled and auto-sent.
- **The float-up.** A placeholder ("Ask anything…") sits over the seed; the **instant the user types**, it animates up off the seed (a `BubbleMorph`-spirit spring) making room for the thread. **Enter sends.** The canvas panel becomes key/main while a field is focused (extends `setCanvasInteractive`) so the keyboard reaches the field — while the two-finger gesture compass (recognized off the multitouch device, not window events) keeps resolving.
- **Multi-turn thread.** The assistant streams a reply (`.conversing`), the user types again → placeholder floats again → Enter sends. The running thread renders user/assistant turns through the existing **collapsible thinking section** + **BidiText**, with live streaming of the in-flight assistant turn.
- **The unification — a preset IS a pre-filled turn 1.** Quick actions (Fix Grammar) auto-send a canned turn 1 with `output = replaceSelection` and **DOWN extracts the latest assistant turn** to that target; "Ask…" is an **empty turn 1**, `output = previewOnly`, and the thread keeps going. Same canvas, same state machine — the output target governs only **what DOWN does at the seam**, never the thread shape.
- **Bare-seed defaults.** "Send just the copied text/image with no question" gets a sane **default question per seed type** (image → describe / what-is-this; text → summarize / explain) so a bare seed is a valid turn 1, never an empty model call.
- **The gesture compass (canonical).** In the canvas, two-finger: **DOWN = affirm** (extract the latest assistant turn to the output target / approve a tool step) and fires **only when `canvasAtTop`**; **UP = scroll**, and **overscroll-past-bottom = PARK** to the notch (hand-off to `ai-parked-sessions`); **RIGHT = discard**; **LEFT = reserved**; **Enter = send**. The scroll/affirm verb collision is resolved by the at-top gate (DOWN off-top is scroll) and the resolve excursion sitting above incidental two-finger scroll (`canvasResolveThreshold`).
- **One-source discipline.** The seed is the **one** source (turn 1); follow-up turns are **pure text** (no new attach). An explicit attach-new-seed gesture is noted as a **documented future**, not silently allowed.

## Capabilities

### Modified Capabilities

- `ai-command-band`: the AI command canvas becomes a **typed, multi-turn conversational canvas** — open-showing-the-seed-and-waiting (no auto-fire), the typing float-up, multi-turn send/stream, a preset unified as a pre-filled turn 1, bare-seed defaults per seed type, and the canonical two-finger compass (DOWN affirm-at-top / UP scroll & overscroll-park / RIGHT discard / LEFT reserved / Enter send) with the at-top scroll/affirm collision resolved. The one-shot preset behavior is preserved as a special case of the same machine.

## Impact

- **Code (MLX-free Core):** the canvas-owned additive `AICommandExecutor.State` cases (`.awaitingSeed`, plus consuming `.conversing`/`.awaitingTurn`/`.awaitingApproval`/`.parked`) + the seed/send/affirm/park interpretation; a pure `BareSeedDefault` resolver (seed type → default question); a pure overscroll-park decision read at the `AppCoordinator` seam.
- **Code (overlay, `xcodebuild` compile-verify only):** `AICommandCanvasView` grows a thread renderer + a focusable composer with the float-up animation and `@FocusState`; `LauncherOverlayController.setCanvasInteractive` extends to a **field-focus** key/main flip; `AppCoordinator.launcherCanvasResolve` reads `canvasAtBottom` for overscroll-park and `Enter` sends the turn.
- **Consumes (do NOT redefine):** `AgentConversation`/`AgentMessage`/`AgentSessionID`/`AgentTurn` + `.conversing`/`.awaitingTurn` (`ai-conversation-runtime`); the `AgentLoop` observable loop state + `ApprovalGate` DOWN=approve/RIGHT=skip (`ai-tool-routing`); `OverscrollPark.shouldPark` + the restore entry point + `canvasAtBottom` companion (`ai-parked-sessions`).
- **Verification:** the executor seed/send/affirm/park machine, `BareSeedDefault`, and the canvas-resolve interpretation are pure Core, `swift test` with `StubLLMRuntime` scripting full typed conversations; the SwiftUI float-up + `@FocusState` + key/main flip are `xcodebuild` compile-verified and **user run-verified** in a stable-signed build (an agent never builds/signs/installs the `.app`).
- **Out of scope:** the conversation types & compaction (`ai-conversation-runtime`), the route loop & registry (`ai-tool-routing`), the parked store/rail/scheduler (`ai-parked-sessions`), the batched runtime (`ai-batched-runtime-and-context`), an attach-new-seed gesture (documented future), and any Intel/low-end fallback (M5/M4-only).
