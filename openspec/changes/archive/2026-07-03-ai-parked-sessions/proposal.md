## Why

The V2 agent is conversational, tool-using, and **background-capable**: a turn may dispatch a long tool chain, a web/Claude handoff, or a memory edit that the user does not want to babysit. Today the AI canvas is a single foreground surface — when you swipe it away the work is *gone*; there is no place for a conversation to keep running while you do something else, and no ambient way to learn that a backgrounded session finished or needs you.

This slice gives the agent a **home**. Scrolling the canvas to the bottom and pulling past it flies the conversation **up into the notch** (or, on a notchless/external display, a top-center menu-bar tab) where it lives as a **parked session**: a durable, identity-stable `AgentConversation` the batched runtime may advance in the background. A cursor-to-notch reveal drops a **rail** of parked cards below the notch — each badged with its live state (thinking / done / needs-you / failed) — and pulling a card back makes it the active canvas again. The make-or-break signal is **needs-you**, surfaced as a **peripheral notch glow**: never a modal, never a bounce — an ambient cue you notice only when you choose to.

It also defines the **scheduler seam** the batched-runtime slice plugs into: in this slice exactly **one** generation is active and the rest are queued (a deterministic, `swift test`-able policy), but the `ParkScheduler` interface is shaped so the batched runtime can fill **K** slots at once as a pure drop-in — no scheduler rewrite when batching lands. And it owns the **lifecycle**: a max parked count, an idle timeout that summarizes-and-sleeps (drops the KV cache, keeps a one-line resume on disk), and discard semantics where pending generation is cancelled via `Task` cancellation but **completed side effects cannot be rolled back**.

This is the V2 evolution of the AI feature on Apple-Silicon M5 — the hardware is exactly why background/batched sessions are in scope at all. Nothing here forks an existing seam: the rail reuses the `DockPreviewOverlay` pattern (non-activating mouse-interactive panel, edge-gated `GlobalCursorMonitor`, orientation-aware anchoring, synchronous `orderOut` teardown), the fly-up reuses `BubbleMorph`, the park trigger is the canonical two-finger overscroll-past-bottom interpreted at the `AppCoordinator` seam (the recognizer is untouched), and the conversation types come verbatim from `ai-conversation-runtime`.

## What Changes

- **Overscroll-park.** Scrolling the canvas to the bottom and continuing the two-finger UP excursion *past* the bottom (a single overscroll threshold above incidental scroll) flies the canvas **up** and shrinks it into the notch home zone via `BubbleMorph` (the documented "first spring," scale-toward-`seedScale` + opacity, here playing the fly-up/recede side). Interpreted at the consumer (`AppCoordinator`), not the recognizer.
- **The notch home zone.** An interactive **non-activating** panel anchored **top-center**, the parked sessions' resting place. It MUST degrade gracefully: on a notched display it tucks under `safeAreaInsets.top` (the `ReceiveHUD` precedent); on a notchless/external display it becomes a **top-center menu-bar tab** — never a hard dependency on a physical notch. Reuses the `DockPreviewOverlay` panel species + orientation-aware anchoring (here: top-center, clamped on-screen).
- **State badges per parked card.** Each parked card carries a `ParkState` badge — **thinking / done / needs-you / failed** — driven by the scheduler + the routing loop's observable state. The **needs-you** signal also raises an **ambient notch glow** (peripheral, non-intrusive) so the user learns a parked session escalated without a modal interruption.
- **The rail.** Cursor → notch reveals a horizontally-**scrollable** row of parked cards hanging below the notch; pulling a card back (click/drag-down) **restores** it as the active canvas. Reuses the `DockPreview` cursor-edge reveal (edge-gated `GlobalCursorMonitor`, synchronous teardown).
- **The session scheduler.** Multiple parked sessions; in **this slice exactly one** active generation, the rest queued (FIFO with needs-you/escalation priority and `nextRunAt` honoring). The `ParkScheduler` protocol (`runnableSessions(now:maxSlots:)` / `didAdvance` / `escalate`) is the seam the batched runtime fills: `maxSlots == 1` here, `maxSlots == K` is a drop-in — no scheduler change.
- **Lifecycle.** A configurable **max parked count** (evicts the least-recently-updated *idle* session, never an active/needs-you one); an **idle timeout** → **summarize-and-sleep** (a one-line resume summary persisted, the KV cache dropped — owned by the batched-runtime slice, requested through a seam here); **discard** = cancel pending generation via `Task` cancellation, drop the durable conversation, and **explicitly state that completed side effects are NOT rolled back** (a fired calendar write stays fired).
- **Durable store.** A `Codable` `AgentConversation` store (owned here per the blueprint) so a parked session survives relaunch with its one-line resume; the runtime slice owns the *types*, this slice owns the *store*.

## Capabilities

### New Capabilities

- `ai-parked-sessions`: the background-without-interfering model — overscroll-park, the notch home zone (notch-or-tab degradation), per-card state badges + the ambient needs-you notch glow, the cursor-reveal rail with pull-back-to-active, the one-active-now/`ParkScheduler`-is-the-batching-seam scheduler, and the park/sleep/discard/evict lifecycle with a durable conversation store.

## Impact

- **Code (mostly MLX-free Core):** new `AI/Parked/` — `ParkState`, `ParkedSession`, `ParkScheduler` (protocol) + `SerialParkScheduler` (the one-active-now pure policy), `ParkedSessionStore` (durable `Codable` store), `ParkLifecycle` (max-count eviction + idle-timeout-to-sleep, pure with injected `now:`), and the overscroll-park decision helper consumed at the `AppCoordinator` seam. All pure / `swift test`-able.
- **Code (overlays, app target — `xcodebuild` compile-verify only, user run-verifies):** `Overlay/NotchHomeZoneOverlay.swift` (the non-activating panel + rail view, reusing the `DockPreviewOverlay` controller pattern), a `NotchHomeZoneController` wiring `GlobalCursorMonitor` → reveal/teardown + the ambient glow + restore-to-canvas, and the `BubbleMorph` fly-up wiring in `AICommandCanvasView`/its host.
- **Coordination seams (consumed, NOT redefined):** `AgentConversation`/`AgentSessionID`/`AgentMessage` (`ai-conversation-runtime`); `ToolStepResult`/`ToolStepStatus` (`ai-tool-routing`) for `didAdvance`; `BatchedLLMRuntime`/`runnableSessions` (`ai-batched-runtime-and-context`) as the background advancer; `ParkState.needsYou` escalation raised by `ai-background-autonomy` via `ParkScheduler.escalate`; `AIError.message(for:)` for the one error translator.
- **Errors:** one new `ParkError` (Core `LocalizedError`) only for store/persistence failures that `RuntimeError`/`TaskError` cannot carry; mapped at the boundary, surfaced **bounded + non-blocking** (a badge/`failed` card, never `NSAlert.runModal`), routed through `AIError.message(for:)`.
- **No new permission, no gesture relocation, no re-login.** The rail reuses the cursor monitor (no Input Monitoring); the panel is non-activating (no focus steal); park is a consumer-side reading of the existing recognizer output.
- **Out of scope:** the batched MLX execution itself + KV-cache drop/restore mechanics (`ai-batched-runtime-and-context`); the write-policy/audit/whitelist and what *makes* a step `needs-you` (`ai-background-autonomy`); the canvas `State` cases + the seed/float-up/compass UX (`ai-conversational-canvas`, which consumes this slice's park trigger); multi-active scheduling beyond the one-active-now policy (the interface is ready; the K-slot policy is the batched slice's to drive).
